비교 분석 사용법

  • 레이아웃을 2 이상(최대 4)으로 하고 비교할 영상들을 슬롯에 불러옵니다. 3~4개를 불러오면 그중에서 비교할 영상을 고를 수 있습니다.
  • 상단 🔍 비교를 누르면 불러온 영상이 모두 같은 시점으로 맞춰지며 패널이 열립니다.
  • 비교 대상 A/B: 자세히 볼 두 영상을 드롭다운에서 고릅니다. 3~4개를 불러온 경우에도 상세 비교(히트맵·차이 강조 등)는 한 번에 두 영상씩 이뤄집니다.
  • 전체 비교 요약(3개 이상 불러왔을 때만 표시): A로 지정한 영상을 기준으로 나머지 모든 영상과의 전체 차이 %를 한 번에 보여줘, 어떤 영상이 가장 다른지 먼저 파악한 뒤 그 조합을 A/B로 선택해 자세히 볼 수 있습니다. 속도를 위해 항상 정밀(픽셀) 방식으로 계산합니다.
  • −10f / |◀ 1f / 1f ▶| / +10f: 불러온 모든 영상을 함께 프레임 단위로 이동(화면 좌우 드래그, ←/→ 키도 동일)합니다.
  • 정렬의 A/B 각각 ±1f: 현재 선택된 A/B 두 영상의 시작 지점이 어긋나 있을 때 한쪽만 이동시켜 맞춥니다. 위쪽 시간 표시의 "오프셋"이 현재 어긋난 프레임 수입니다.

정밀 비교 (프레임)

같은 시점 두 프레임을 픽셀 단위로 색상 값을 직접 비교합니다. 완전히 동일한 영상(같은 소스를 재인코딩한 경우 등)에서 아주 미세한 차이까지 잡아낼 때 적합합니다.

  • 전체 차이 픽셀 %: 두 프레임에서 값이 다른 픽셀의 비율입니다.
  • 차이가 큰 부분: 화면을 9개 구역(좌측 상단·상단·…·우측 하단)으로 나눠, 그중 차이 픽셀 비율이 높은 순서대로 보여줍니다.
  • 차이 강조/겹쳐보기/A만/B만: 차이 강조는 다른 픽셀을 핑크로 표시, 겹쳐보기는 두 프레임을 반씩 섞어 표시, A만/B만은 한쪽만 그대로 표시합니다.
  • 민감도: 오른쪽으로 갈수록 더 작은 색상 차이도 "다르다"고 판정합니다. 인코딩 과정에서 생기는 미세한 노이즈까지 잡히면 왼쪽으로 낮추세요.
  • 화질·해상도·인코딩이 조금만 달라도 같은 화면이 다르다고 나올 수 있습니다 — 그런 경우 아래 느슨한 비교를 사용하세요.

느슨한 비교 (동작)

픽셀 색상이 완전히 같은지가 아니라, 화면의 각 영역에서 실제로 얼마나/어떻게 움직이는지를 비교합니다. 현재 지점부터 짧은 구간(약 10프레임)을 두 영상에서 함께 재생하듯 훑으며, 프레임이 바뀔 때마다 생기는 밝기 변화량을 "움직임의 양"으로 계산합니다. 이 방식은 화질·노출·인코딩 차이에는 덜 민감하고, 동작 자체가 다른 경우(한쪽은 움직이는데 다른 쪽은 멈춰 있다, 움직이는 양이 다르다 등)를 잡아내는 데 적합합니다.

  • 동작 차이 점수: 두 영상의 "영역별 움직임 분포"가 얼마나 다른지를 0~100 사이 값으로 나타냅니다. 0에 가까울수록 두 영상의 움직이는 패턴(어디가 얼마나 움직이는지)이 비슷하고, 값이 클수록 동작 자체가 다릅니다.
  • 차이가 큰 부분: 9개 구역 중 두 영상의 움직임 비중 차이가 큰 순서대로 보여줍니다.
  • "A만 움직임" / "B만 움직임": 해당 구역에서 한쪽 영상은 뚜렷하게 움직이는데 다른 쪽은 거의 정지해 있는 경우 표시됩니다. 동작 유무 자체가 다른, 가장 눈에 띄는 차이입니다.
  • 움직임 민감도: 오른쪽으로 갈수록 더 작은 움직임 차이도 "다르다"고 판정합니다.
  • 분석은 현재 지점부터 약 10프레임 구간을 스캔하므로 정밀 비교보다 계산에 1~2초 더 걸릴 수 있습니다. 두 영상 모두 이 구간에서 움직임이 거의 없으면 "움직임이 거의 없습니다"로 표시됩니다.

참고

  • URL로 불러온 영상은 서버가 CORS(교차 출처 접근)를 허용해야 두 모드 모두 분석 가능합니다. 파일 앱에서 불러온 영상은 제한 없이 분석됩니다.
  • 두 영상의 해상도가 다르면 자동으로 같은 크기로 맞춰 비교합니다.
